Development inspection and worker controls. This technical screen is separate from the product panel.

The Read buttons inspect only. Binding and Poll now can arm the worker, advance paid Test Mode gateways, fill fields, or create unpaid notifications. For the initial read-only validation, do not use binding, polling, or baseline reset. No automatic login, payment, appointment submit, or final confirmation is implemented.

Read-only live adapter checks. Click the extension toolbar icon on the matching official page first, then run the matching read here. Identifiers stay in the worker; only counts come back.

Live group binding for a separately agreed worker test. Save your paid/unpaid IVRs in configuration first; use synthetic email/password for manual-login testing. Select the dashboard with the toolbar icon, then resolve. Binding persists a probe-owned run and can arm later worker execution; it is not an inspection-only test.

Poll control. Binds a deadline of now on the running bound run; the alarm loop still plans, budgets, and executes.

Local developer diagnostics: bounded, event-driven, allowlisted fixed codes only (never credentials, URLs, identifiers, appointment dates, or page content). Retained about seven days and never cleared by a successful run. Export the JSON below when reporting an unattended-run issue.
